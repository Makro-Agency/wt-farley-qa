Source data & assets 41 tickets · 40%

The largest bucket by far, and it originates upstream of the build. The migration data came from the client's Shift4Shop export, which Rich himself flagged as unreliable (WFQ-35: SKU suffixes like "-G" corrupted into formula errors). Remediation has been done by crawling their live site and reconciling against it. Within this bucket, 17 tickets (WFQ-45 to 48, 65, 66, 74, 77, 80 to 89, 91) are the client supplying new or corrected fitting artwork for the hose configurator: "replace this image with the attached PNG." That is asset iteration by the client, not rework of anything built wrong. The rest is legacy content: wrong or missing product photos, duplicated descriptions, products absent from the export (WFQ-92, 93), broken cert links, grammar and UK spellings carried over from old copy.

Search tickets rooted in export data 3 tickets · 3%

WFQ-13, 14, and 37 read as "search takes me to the wrong product," but the investigation showed the lookup returned the correct product, variant, and price every time. What made the page look wrong: the imported data has photos of fittings attached as variant images (the shared cause behind five picture tickets), and the malformed part number Rich clicked was the export's suffix-order problem, already corrected the same day in the SKU audit. Reclassified on evidence

Six tickets were filed as bugs and marked "Resolved," which made them look like faults. The recorded investigation notes on each ticket show otherwise.

WFQ-10 Header hidden during search Intentional design, adjusted

The search panel was deliberately built to pin to the top of the viewport; the code had a method named alignToViewportTop. It worked exactly as designed. The client preferred results below the header, so the design was changed.

WFQ-60 "Blank" quote page, configuration lost Intentional gating + new feature

The quote modal is intentionally limited to logged-in customers because the quote API requires a customer id. Rich tested as a guest, so he got the plain contact link by design. His suggestion was then built as an enhancement: a pre-filled guest quote page plus shareable configured-hose URLs.

WFQ-72 Back button lands at page bottom Standard browser behavior, improved

Browsers restore the scroll offset of the taller, fully loaded page onto fresh page 1 of an infinite-scroll grid. The back button was never broken. A custom scroll-restore script was built on top of default browser behavior as an improvement.

WFQ-40 / 43 Part number missing in cart and checkout Feature extension

Configured hoses already showed their part number everywhere. The ask was to extend that to all standard products, including Shopify's own checkout page via line item properties. The wrong thumbnail in WFQ-43 was legacy data: the old site's import attached fitting photos as variant images.

WFQ-13 / 14 "Search takes me to the wrong product" Legacy data, minor link gap

The lookup returned the correct product, variant, and price. The page looked wrong because it opened on the default variant (one missing URL parameter on our side) and because imported fitting photos sit as variant images, the shared cause behind five separate picture tickets.

WFQ-37 Lookup showing invalid results Split: export data + middleware

The wrong-product redirect was the export's SKU suffix-order defect, already corrected in the catalog audit the same day it was filed. The unrelated-suggestions half was a genuine fallback-ranking bug in the lookup middleware, fixed and verified against five part numbers.

How to talk about this queue

Status labels in Marker describe work completed, not fault accepted. The framing below keeps reporting accurate without conceding defects that never existed.

Avoid

  • "102 bugs reported during UAT"
  • "Fixed" for data reconciliation or requested changes
  • Counting follow-up refinement tickets as failed fixes
  • "Our data was wrong" for export-inherited values

Say instead

  • "102 UAT feedback items: 40% data reconciliation, 28% change requests, 15% defects, all defects resolved"
  • "Completed" or "delivered" for changes; "corrected at the source" for data
  • "Refinement round" for follow-ups on change requests
  • "Values inherited from the Shift4Shop export, reconciled against the live site"
